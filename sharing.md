# 📌 FEATURE: Шеринг заметок

---

# 1. User Stories

## 1.1. Общий доступ к заметкам (раздел)

### US-S-01. Просмотр общего доступа

Как пользователь мобильного приложения, я хочу видеть раздел “Общий доступ”, чтобы просматривать заметки, которыми со мной поделились или которые я сам открыл другим пользователям.

**Критерии приемки:**

* В списке папок отображается системный раздел “Общий доступ”
* После входа в раздел отображается список заметок
* Список поддерживает фильтрацию:

  * “Владелец: Я”
  * “Владелец: Не я”
* Данные получаются через API `GET /v1/notes/shared?isMine=true&page=0&pageSize=10`
* Интерфейс списка аналогичен списку обычных заметок

---

## 1.2. Просмотр заметки по ссылке

### US-S-02. Открытие заметки по диплинку

Как пользователь, я хочу открывать заметку по ссылке, чтобы просматривать её содержимое без входа в структуру папок.

**Критерии приемки:**

* Пользователь может открыть заметку по диплинку формата
  `scom://deeplink/notes/folders/shared/notes?token=...`
* Система получает token и загружает заметку
* Пользователь попадает в режим просмотра заметки
* Редактирование зависит от прав доступа

---

## 1.3. Шеринг заметки

### US-S-03. Управление доступом к заметке

Как владелец заметки, я хочу управлять доступом к заметке, чтобы контролировать, кто может её просматривать или редактировать.

**Критерии приемки:**

* В экране заметки есть кнопка “Шеринг”
* Открывается bottom sheet с настройками доступа
* Можно:

  * добавить пользователя через поиск
  * изменить роли пользователей
  * изменить общий режим доступа
* Поддерживаются роли:

  * viewer (зритель)
  * commenter (комментатор)
  * no access (закрыть доступ)

---

### US-S-04. Копирование ссылки на заметку

Как пользователь, я хочу скопировать ссылку на заметку, чтобы поделиться ей с другими людьми.

**Критерии приемки:**

* В bottom sheet есть кнопка “Скопировать ссылку”
* При открытии шеринга выполняется `GET /notes/{noteId}/share`
* Система получает `token`
* Ссылка формируется как:
  `scom://deeplink/notes/folders/shared/notes?token={token}`
* Ссылка копируется в буфер обмена
* Показывается snackbar об успехе

---

### US-S-05. Настройка публичности заметки

Как владелец заметки, я хочу выбирать уровень доступа, чтобы определить кто может её видеть.

**Критерии приемки:**

Доступы:

1. Только я

   * `isActive = false`
   * `isPublic = false`

2. Пользователи заметки

   * `isActive = true`
   * `isPublic = false`

3. Все по ссылке

   * `isActive = true`
   * `isPublic = true`

Запрос:
`PUT /notes/{noteId}/share`

# 2. Use Cases

---

## 2.1. Общий доступ

### UC-S-01. Получение списка shared заметок

**Цель:** показать пользователю список заметок с доступом

**Основной сценарий:**

1. Пользователь открывает раздел “Общий доступ”
2. Система определяет фильтр (isMine)
3. Система вызывает:
   `GET /v1/notes/shared?isMine=true&page=0&pageSize=10`
4. Система получает список заметок
5. Система отображает список

---

### UC-S-02. Переключение фильтра

**Цель:** фильтрация заметок по владельцу

1. Пользователь выбирает фильтр “Я / Не я”
2. Система обновляет параметр `isMine`
3. Система повторно вызывает API списка shared заметок
4. Список обновляется

---

## 2.2. Диплинк

### UC-S-03. Открытие заметки по ссылке

**Цель:** открыть доступную заметку без навигации по структуре

1. Пользователь открывает диплинк
2. Система извлекает `token`
3. Система вызывает API получения заметки по token
4. Система проверяет права доступа
5. Система открывает экран заметки

---

## 2.3. Шеринг внутри заметки

### UC-S-04. Открытие шеринга

1. Пользователь нажимает кнопку “Шеринг”
2. Система открывает bottom sheet
3. Система вызывает `GET /notes/{noteId}/share`
4. Система получает:

   * token
   * список пользователей
   * текущие права

---

### UC-S-05. Добавление пользователя

1. Пользователь ищет пользователя
2. Система показывает результаты поиска
3. Пользователь выбирает человека
4. Система добавляет пользователя в список
5. Система обновляет права доступа

---

### UC-S-06. Изменение роли пользователя

1. Пользователь открывает список участников
2. Выбирает роль:

   * viewer
   * commenter
   * no access
3. Система сохраняет изменения локально/в UI state
4. При сохранении отправляет обновление на сервер

---

## 2.4. Управление доступом

### UC-S-07. Изменение общего доступа

1. Пользователь выбирает режим доступа
2. Система маппит:

   * private
   * shared users
   * public link
3. Система вызывает:
   `PUT /notes/{noteId}/share`
4. Система обновляет состояние доступа

---

## 2.5. Копирование ссылки

### UC-S-08. Копирование диплинка

1. Пользователь нажимает “Скопировать ссылку”
2. Система проверяет наличие token
3. Система формирует диплинк:
   `scom://deeplink/notes/folders/shared/notes?token=...`
4. Система копирует ссылку в буфер
5. Система показывает snackbar
